# 02 설명 — S3가 있어도 로컬 저장 공간이 필요한 이유

저장 도구가 받은 데이터를 모두 즉시 S3에 쓰지는 않습니다. 먼저 가까운 디스크에 기록하고, 여러 기록을 모아 S3로 보내기도 합니다.

**S3 호환 저장소**는 S3 방식의 요청으로 객체를 저장하고 읽을 수 있는 저장소입니다. 이번에는 가벼운 로컬 실습용 SeaweedFS를 사용합니다. 클라우드 계정 없이 S3 연결을 배울 수 있습니다. `bucket`은 객체들을 담는 저장 공간의 이름입니다.

**WAL**은 받은 데이터를 처리하기 전에 남기는 기록입니다. 작업 중 Pod가 재시작되어도 디스크에 남은 기록을 읽어 다시 처리하는 데 도움이 됩니다. S3의 장기 저장 역할과 로컬 WAL의 역할은 다릅니다.

Pod 내부의 임시 파일은 Pod와 함께 사라질 수 있습니다. 따라서 데이터를 지속해서 보관할 디스크 연결을 사용합니다. Kubernetes의 **PVC**는 애플리케이션이 요청하는 저장 공간이고, **PV**는 그 요청에 연결되는 실제 공간입니다.

이번 실습에서는 worker 노드의 폴더를 WSL 관리 폴더에 연결합니다. SeaweedFS 데이터, 백엔드 WAL, Alloy 상태, Grafana Dashboard DB를 그곳에 저장합니다. 클라우드의 관리형 디스크와 같은 고가용성 구성은 아닙니다.

| 버킷 | 사용할 도구 |
|---|---|
| mimir-blocks | Mimir |
| loki-data | Loki |
| tempo-traces | Tempo |

Pod 재시작에는 저장 파일을 유지하고, 실습을 끝내는 `destroy`에서는 이 폴더까지 삭제합니다.
