# 01 설명 — Observability는 무엇을 보는 것인가요?

서비스가 느리거나 실패했을 때, 내부에서 무슨 일이 일어났는지 알아보는 것이 이 과정의 목표입니다. 이번 실습에서는 세 가지 기록을 함께 봅니다.

| 데이터 | 쉬운 뜻 | 이번 실습의 예 | 저장 도구 |
|---|---|---|---|
| 메트릭(metric) | 시간에 따라 기록한 숫자 | CPU 사용률, 요청 수, 응답 시간 | Mimir |
| 로그(log) | 어떤 일이 있었는지 적은 기록 | 요청 시작, 처리 완료, 오류 메시지 | Loki |
| 트레이스(trace) | 요청 하나의 이동 경로와 처리 시간 | Spring Boot → FastAPI 호출 | Tempo |

메트릭은 전체 변화와 이상 징후를 찾기 좋습니다. 로그는 당시 어떤 일이 발생했는지 읽기 좋습니다. 트레이스는 느린 요청이 어느 단계에서 시간을 썼는지 찾기 좋습니다. 세 가지를 함께 보면 숫자에서 발견한 문제를 개별 요청의 기록까지 따라갈 수 있습니다.

Alloy는 수집해서 전달하는 도구입니다. Mimir·Loki·Tempo는 전달받은 데이터를 저장하고 찾아주는 도구입니다. Grafana는 그 데이터로 그래프·로그·처리 시간 막대를 보여주는 화면입니다. 데이터를 저장하는 곳과 보는 화면을 구분하면 전체 구성이 쉬워집니다.

우리는 처음부터 모든 것을 설치하지 않습니다. 저장 공간 → 저장 도구 → 수집기 → 화면 순서로 하나씩 준비합니다.
