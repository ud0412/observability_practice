# 16 설명 — 재시작과 실습 종료는 다른 작업입니다

Pod가 죽으면 Kubernetes가 새 Pod를 만들 수 있습니다. 디스크를 연결해 두면 새 Pod가 이전 파일을 읽습니다. 그래서 저장된 관측 데이터와 직접 만든 Dashboard는 계속 볼 수 있습니다.

이번 보존 실습은 저장소에 도착한 데이터, PVC와 WAL의 기록을 확인합니다. 앱이나 수집기의 전송 전 메모리까지 무손실이라고 보장하는 실습은 아닙니다. 데이터 보존 기간은 기본 24시간입니다.

실습을 끝내는 destroy는 전용 클러스터를 삭제하고 WSL의 관리 데이터 폴더까지 제거합니다. Observability 저장소의 destroy는 선행 저장소의 소유권·삭제 구현을 호출합니다. 두 과정이 쓰는 하나의 실습 환경이므로 Kubernetes 기반까지 함께 종료됩니다.

삭제에는 수동 배포한 sample-app, S3 객체와 metadata, WAL, Alloy 상태, Grafana Dashboard DB, 생성 키, kubeconfig, 관리 exports·로그·접속 프로세스가 포함됩니다. 교본 소스와 공용 도구·이미지 캐시는 학습 소스/공유 자산이므로 삭제하지 않습니다.

대시보드 export를 관리 폴더 밖에 복사하면 destroy가 그 복사본까지 찾을 수 없습니다. 따라서 기본 export 경로를 사용합니다.
